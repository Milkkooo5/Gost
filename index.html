2. Стандарты

Определения

Стандартизация — деятельность по установлению положений для многократного применения ради упорядочения. Стандарт — документ с характеристиками, правилами, принципами для объектов стандартизации. Применение стандартов в общем случае добровольное, но может стать обязательным по закону или договору.

162-ФЗ — о стандартизации; 184-ФЗ — о техническом регулировании. Технический регламент устанавливает обязательные требования; стандарт — стандартизованные положения и способы их выполнения.

Объект стандартизации — всё, что можно унифицировать: материалы, компоненты, оборудование, системы, правила, процедуры, методы, функции.

Область, объект, аспект

  • Область — в какой сфере (системная и программная инженерия).
  • Объект — что стандартизируют (процессы ЖЦ ПС).
  • Аспект — какая сторона объекта (состав, назначение, результаты процессов).

Как читать обозначение

ГОСТ Р ИСО/МЭК 12207-2010: ГОСТ Р — национальный; ИСО/МЭК — основа международного стандарта ISO/IEC; 12207 — регистрационный номер; 2010 — год принятия (не дата введения в действие). Основа — ISO/IEC 12207:2008.

В ГОСТ 1.5-2001 регистрационный номер — 1.5 (1 — комплекс, 5 — номер в комплексе). В ГОСТ 19.201-78: 19 — комплекс ЕСПД.

4. Жизненный цикл и модели

ЖЦ ПО — от замысла до прекращения применения: требования → проектирование → реализация → интеграция и тестирование → эксплуатация и сопровождение → снятие с эксплуатации.

Процесс — деятельность, преобразующая входы в выходы. Стадия — часть жизни во времени. Модель ЖЦ — порядок стадий и переходов. Стандарт процессов (12207) не навязывает модель.

МодельСутьКогда
КаскаднаяПоследовательные стадииСтабильные требования
V-модельКаждому уровню проектирования — свой уровень проверкиРаннее планирование испытаний
ИтерационнаяРешение уточняется цикламиНеопределённость
ИнкрементнаяПродукт наращивается частямиРанняя поставка
СпиральнаяКаждый виток — анализ рисковВысокие риски
«Круговая», «вертикальная», «свободная», «линейная» модели — не существуют, это дистракторы.

Профиль стандартов — согласованный набор выбранных стандартов для конкретной системы/проекта. Адаптация — выбор применимых процессов с учётом масштаба, рисков, ресурсов, договора.

5. Группы процессов

ГОСТ Р ИСО/МЭК 12207-2010 — 7 групп

Процессы в контексте системы:

  1. Соглашения: приобретение, поставка.
  2. Организационное обеспечение проекта: менеджмент модели ЖЦ, инфраструктуры, портфеля проектов, людских ресурсов, качества.
  3. Процессы проекта: планирование, оценка и управление, менеджмент решений, рисков, конфигурации, информации, измерения.
  4. Технические: определение требований правообладателей, анализ системных требований, проектирование архитектуры системы, реализация, комплексирование, квалификационное тестирование, инсталляция, поддержка приёмки, функционирование, сопровождение, прекращение применения.

Специальные процессы ПО:

  1. Поддержка ПО: менеджмент документации, менеджмент конфигурации ПО, обеспечение гарантий качества, верификация, валидация, ревизия, аудит, решение проблем.
  2. Реализация ПО: реализация, анализ требований ПО, проектирование архитектуры ПО, детальное проектирование, конструирование, комплексирование, квалификационное тестирование ПО.
  3. Повторное применение ПО: проектирование доменов, менеджмент повторного применения активов и программ.

ГОСТ Р 57193-2025 (системы) — 4 группы

  • Соглашения: приобретение, поставка.
  • Организационное обеспечение: модель ЖЦ, инфраструктура, портфель, человеческие ресурсы, качество, управление знаниями (новое).
  • Техническое управление: планирование, оценка и контроль, решения, риски, конфигурация, информация, измерения, гарантия качества.
  • Технические: анализ бизнеса/назначения, потребности заинтересованных сторон, системные требования, архитектура, проект, системный анализ, реализация, комплексирование, верификация, передача, валидация, функционирование, сопровождение, изъятие.

ГОСТ Р ИСО/МЭК ТО 15271-2002 — 3 класса

  • Основные: приобретение, поставка, разработка, эксплуатация, сопровождение.
  • Вспомогательные: документирование, конфигурация, обеспечение качества, верификация, аттестация (валидация), совместный анализ, аудит, решение проблем.
  • Организационные: управление, инфраструктура, усовершенствование, обучение.
Запомни: 12207-2010 → 7, 57193-2025 → 4, 15271 → 3. Отвечая, всегда называй документ и год.

6. Требования, проверки, дефекты

Требования

Порядок разработки: выявление и сбор → анализ → документирование → утверждение.

Уровни: бизнес-требования (зачем) → пользовательские (что делает пользователь) → функциональные (что делает система).

  • Функциональные — действия: создать запись, отменить.
  • Нефункциональные — свойства: производительность, надёжность, безопасность.
  • Хорошие требования: понятны, непротиворечивы, выполнимы, проверяемы, прослеживаемы.
  • Трассируемость — связь потребность → требование → решение → код → тест.

Проверки

ПонятиеВопрос
ВерификацияСоответствует ли результат заданным требованиям?
ВалидацияУдовлетворяет ли система потребности при реальном использовании?
Ревизия / совместный анализКакие проблемы выявлены при совместном рассмотрении?
АудитЕсть ли объективные свидетельства соответствия критериям?

Дефекты

Ошибка человека → дефект в результате → отказ при определённых условиях. Первичные ошибки — причины, вторичные — проявления. Полное тестирование сложной системы невозможно, поэтому приоритет по риску.

8. Сопровождение и конфигурация

Сопровождение — управляемые изменения ПО: исправление, адаптация, улучшение, предупреждение.

Порядок изменения: зарегистрировать → воспроизвести → оценить влияние → согласовать → изменить код и документы → проверить + регрессия → выпустить.

Управление конфигурацией: идентификация → контроль изменений → учёт состояния → аудит → выпуск. Baseline — зафиксированный согласованный набор элементов. Git хранит версии, но не заменяет процедуры согласования.

Стандарты: 14764 — сопровождение; 15846 — конфигурация; 16326 — управление проектами; 15271 — руководство по применению 12207.

9. Сертификация

Сертификация — подтверждение соответствия третьей стороной. Подтверждает соответствие конкретного объекта конкретным требованиям, но не отсутствие всех дефектов.

  • Добровольная — по инициативе заявителя. Обязательная — когда требуют применимые нормы.
  • Объекты: программный продукт, процессы, СМК организации (ISO 9001), средства защиты информации.
  • Не сертифицируют сотрудников в рамках сертификации качества продукции и предприятий.

Цели и принципы сертификации (Л3)

  • Задачи и эффективность обязательной и добровольной сертификации ПС.
  • Стандартное определение понятий и компонентов процессов сертификации.
  • Распределение потребностей в сертификации между производителями и заказчиками.

ФСТЭК

Роли: ФСТЭК (федеральный орган), орган по сертификации, испытательная лаборатория, заявитель. Сертификация ФСТЭК обязательна, но проводится не по техрегламентам, а по требованиям приказа ФСТЭК России от 03.04.2018 № 55 (Положение о системе сертификации СЗИ).

Порядок: заявка → анализ документов → программа испытаний → испытания/аудит → протокол → исправления → решение и сертификат → инспекционный контроль.

Профиль защиты — требования к типу объектов; задание по безопасности — к конкретному объекту. Новая сборка не становится сертифицированной автоматически.

Безопасная разработка: SDL, DevSecOps, Security Champion; статический анализ — код без запуска, динамический — работающее приложение.

10. Интеллектуальная собственность

  • Автор — физлицо-создатель. Правообладатель — владелец исключительного права (автор, работодатель, приобретатель). Пользователь — получает разрешённые способы использования.
  • Программа охраняется как литературное произведение. Охраняется форма выражения, а не идея, метод или язык.
  • Литеральные элементы: исходный код, объектный код, промежуточные формы (псевдокод). Нелитеральные: интерфейс, изображения, звуки, аудиовизуальные отображения.
  • Регистрация для возникновения прав не нужна, она добровольна.
СпособСуть
ОтчуждениеИсключительное право передаётся полностью
Лицензионный договорПраво использования в определённых пределах
Простая (неисключительная) лицензияПравообладатель может давать лицензии другим
